# 工业环境检测系统 · 下位机通信协议

**版本** v1.0 · **更新** 2026-10-13
**适用** 下位机（STM32F407ZGT6）↔ 上位机（PC / Qt）之间的串口链路
**对应代码** `App/host_proto.c`（本文件是它的规格说明；改协议请同步改两处）

---

## 一、物理层

协议跑在**两条链路**上，**同一套帧格式**：

| | 调试链路 | 上位机链路 |
|---|---|---|
| 接口 | USART2 | USART6 |
| 收发器 | CH340（USB 转 TTL） | MAX3485（RS485） |
| 引脚 | **PA2 = TX**、**PA3 = RX** | **PC6 = TX**、**PC7 = RX** |
| 方向控制 | — | **PC8 = `RS485_DE`**（高 = 发送，低 = 接收） |
| 用途 | 下位机调试（串口助手直接看） | 上位机（Qt）、RS485 组网演示 |
| 上位机侧 | CH340 的 RXD/TXD | USB 转 485 适配器 |

**两条链路共用的参数**：

| 项 | 值 |
|---|---|
| 波特率 | **115200** |
| 数据位 / 停止位 / 校验 | **8 / 1 / None** |
| 流控 | 无 |
| 共地 | **必须** |

**两条链路是独立的**：各自的接收状态（行缓冲、诊断计数器）分开，
可以同时收发、互不影响。遥测每 500ms 在两条链路**各发一帧**；
命令从任一条链路收到都生效。

> 注意：遥测帧里的 `RXB/RXL/RXO` 是**那条链路自己的**接收统计 ——
> 同一时刻两条链路组出来的帧内容不完全相同，这是有意的。

### 四个常见的接线错误（前两个都实际踩过）

**1. MAX3485 的 `TXD`/`RXD` 接反** —— ⚠️ **这个实际踩过**

模块上印的 `TXD`/`RXD` 有**两种相反的命名习惯**：

| 命名视角 | 含义 | MCU 该怎么接 |
|---|---|---|
| 站在 **MCU** 视角（多数） | "TXD" = 接 MCU 的 TXD | MCU_TX → 模块TXD（直连） |
| 站在 **模块自己**视角 | "TXD" = **模块的发送输出** | MCU_RX ← 模块TXD（**交叉**） |

本项目这块模块是**第二种**，所以必须交叉：
**`PC6`(MCU_TX) → 模块 `RXD`，`PC7`(MCU_RX) ← 模块 `TXD`**。

> 光看丝印名字判断不了是哪种。**第一次接就把两根线当成"不确定"对待，
> 不通就先交换一次。**（另一种更靠谱的办法：查模块原理图，
> 看丝印对应的是 MAX3485 的 `DI`（驱动器输入）还是 `RO`（接收器输出）。）

接错时的现象：**收不到数据，或者收到持续一串 `00`** —— 因为电平极性反了，
接收端一直看到"空号"。

**2. RS485 的 A/B 接反**

各家模块对 A/B 的定义也不统一，接反了不会损坏，但会完全收不到或全是乱码。
**不通时这是第一个要试的。**

**3. `RS485_DE`（PC8）必须被驱动**

悬空的话 MAX3485 的 DE//RE 停在 1.65V 附近（芯片输入门限是 2.0V / 0.8V），
驱动器处于**不确定状态**，总线上会出现随机乱码、且**帧长度忽长忽短**。
固件在 `MX_GPIO_Init()` 里把它初始化为**低电平（接收）**，发送时由
`uart_tx_send()` 拉高、发完再拉低。

> 排查手法：把 EN **临时接到 3.3V（常发）**，看数据是否变干净 ——
> 这一刀能把"DE 控制的问题"和"总线接线的问题"分开。

**4. USB-485 适配器被乱码打进去后卡死**

有些适配器进入错误状态后不会自己恢复，**要关掉串口重开、或者拔插一次 USB**。

## 二、帧格式

所有帧（上行、下行**同一套**）都是：

```
$<类型>,<node>[,<key>=<value>]...*<校验><CR><LF>
```

| 部分 | 说明 |
|---|---|
| `$` | 帧起始符 |
| `<类型>` | 帧类型名，**ASCII 字母**。上行是 `ENV`，下行是 `SET` / `FAN` |
| `<node>` | 节点号，**十进制整数**。当前恒为 `1`，是给将来 RS485 多节点组网预留的（见第七节） |
| `<key>=<value>` | 若干键值对，**用逗号分隔**。key 和 value 都是 ASCII |
| `*<校验>` | 星号 + **两位大写十六进制**的校验和 |
| `<CR><LF>` | `0x0D 0x0A` |

### 校验和算法

**`$` 和 `*` 之间的所有字符（不含 `$` 和 `*`）逐字节异或。**

```
payload = "SET,1,T=30"          ← 即 '$' 之后、'*' 之前的那一段
checksum = 'S' ^ 'E' ^ 'T' ^ ',' ^ '1' ^ ',' ^ 'T' ^ '=' ^ '3' ^ '0'
         = 0x53^0x45^0x54^0x2C^0x31^0x2C^0x54^0x3D^0x33^0x30
         = 0x19

完整帧:  $SET,1,T=30*19\r\n
```

> `异或`能检出任意单字节错误，但检不出"两个字节互换位置"和"同一字节重复偶数次"。
> 对 115200 的点对点短接线够用。将来切 RS485、线更长时建议换成 CRC16。

### 行接收规则（下位机侧）

| 规则 | 说明 |
|---|---|
| **行终止符** | `\r`、`\n`、`\r\n` **三种都接受**。上位机发哪种都行，不必刻意对齐 |
| **行长度上限** | 95 个字符（不含终止符）。超长则**整行丢弃**，等下一个终止符重新对齐 |
| **超长后** | 不会污染后续帧 —— 丢弃后缓冲区清零，下一条命令正常收 |
| **解析失败** | 校验不过、格式不对、字段非法 → **整帧丢弃，绝不半途修改配置** |

> **重要**：上位机发送时**必须带行终止符**。少发终止符是本项目实际踩过的坑 ——
> 现象是"命令完全没反应"，而设备侧看起来什么都没发生。详见
> `docs/工业环境检测系统-问题处理.md` 的 P-15。

## 三、上行帧：`$ENV`（下位机 → 上位机）

**周期：每 500 ms 一帧。**

| key | 单位 | 含义 | 取值范围 / 说明 |
|---|---|---|---|
| `T` | ℃ | 温度 | 一位小数，可负。来自 21VOC |
| `H` | %RH | 湿度 | 一位小数。来自 21VOC |
| `CO2` | ppm | eCO2 | 整数。**等效估算值，精度 ±25%**，不是真 CO₂ 测量 |
| `VOC` | ug/m³ | VOC 空气质量 | 整数。来自 21VOC |
| `HCHO` | ug/m³ | 甲醛 | 整数。来自 21VOC |
| `SMK` | — | 烟雾（MQ-2） | 整数 **0~100 相对指数**，不是 ppm |
| `GAS` | — | 有毒气体（MQ-7） | 整数 **0~100 相对指数**，不是 ppm |
| `LUX` | — | 光照（光敏） | 整数 **0~100 相对指数**，不是 lx |
| `ALM` | — | 报警等级 | `0`=正常 `1`=警告 `2`=报警 |
| `LINK` | — | 21VOC 是否在线 | `0`=掉线 `1`=在线 |
| `AUTO` | — | 自动通风开关 | `0`/`1` |
| `MAN` | — | 手动通风开关 | `0`/`1` |
| `RXB` | 字节 | **下行链路诊断**：收到的字节总数 | 见下方说明 |
| `RXL` | 帧 | 收满的行数 | |
| `RXO` | 帧 | 校验通过并生效的命令数 | |
| `SPT` | ℃ | 设备**当前实际在用**的温度阈值 | 一位小数 |
| `SPH` | %RH | 湿度阈值 | 一位小数 |
| `SPC` | ppm | CO₂ 阈值 | 整数 |
| `SPS` | — | 烟雾阈值 | 整数 |
| `SPG` | — | 有毒气体阈值 | 整数 |
| `SPL` | — | 开灯阈值（低于此值开灯） | 整数 |

### 三个必须知道的语义

**① `LINK=0` 时，`T` / `H` / `CO2` / `VOC` / `HCHO` 是过期值。**
21VOC 掉线后，那几路保持最后一次的值不变。**上位机记录数据时必须看 `LINK`**，
别把过期值当成实时数据存档。

**② `SMK` / `GAS` / `LUX` 是 0~100 的相对指数，没有绝对物理单位。**
它们由两点标定归一化而来（0 = 干净空气/全暗，100 = 另一端），所以
**换个房间、换个传感器就得重标**。报告里不要写成 ppm / lx。

**③ `SPT`~`SPL` 是"设备实际在用"的阈值，不是界面显示的值。**
调"设了不生效"这类问题时**必须看这几个字段** —— 它们来自固件真正读的那份配置。

### 实时样例（实测）

```
$ENV,1,T=22.3,H=56.6,CO2=362,VOC=6,HCHO=0,SMK=0,GAS=2,LUX=80,ALM=0,LINK=1,...
    ...AUTO=0,MAN=0,RXB=128,RXL=8,RXO=9,SPT=30.0,SPH=70.0,SPC=1000,SPS=15,SPG=15,SPL=30*24
```

（这里为了排版折了行，实际是**一整行**，末尾 `*24` 后紧跟 `\r\n`。）

### 下行链路诊断怎么用

`RXB` / `RXL` / `RXO` 是为排查"我发的命令为什么没反应"设计的。上位机可以直接
用它们给用户提示，不用让用户去猜：

| 现象 | 结论 | 提示用户 |
|---|---|---|
| `RXB` 长时间不涨 | 字节根本没到设备 | 查 TX/RX 接线、共地、波特率 |
| `RXB` 涨、`RXL` 不涨 | 字节到了但凑不出整行 | **行终止符没发**（见第二节） |
| `RXL` 涨、`RXO` 不涨 | 行收满了但校验不过 | 校验和算错了 |
| `RXO` 在涨 | 命令生效了 | — |

## 四、下行帧

### 4.1 `$SET` —— 修改阈值

```
$SET,<node>,<key>=<value>[,...]*<校验><CR><LF>
```

可用的 key 和取值范围：

| key | 对应阈值 | 合法范围 | 说明 |
|---|---|---|---|
| `T` | 温度报警阈值 | **20 ~ 40** ℃ | 支持一位小数 |
| `H` | 湿度报警阈值 | **0 ~ 100** %RH | 支持一位小数 |
| `CO2` | CO₂ 报警阈值 | **400 ~ 2000** ppm | 整数 |
| `SMK` | 烟雾报警阈值 | **0 ~ 100** | 指数 |
| `GAS` | 有毒气体报警阈值 | **0 ~ 100** | 指数 |
| `LUX` | 开灯阈值 | **0 ~ 100** | **低于**此值开灯（方向和其它五个相反）|

**规则**

- **超范围的数值会被钳到边界**，不会报错、也不会把配置设飞。
  例如发 `T=999` 会变成 `T=40`。
- **没出现的字段保持原值**。所以发单个字段（`$SET,1,T=30*19`）只改温度。
- **未知的 key 直接忽略**，方便以后加字段而不破坏旧固件。
- 建议上位机**全量下发**（一次带齐六个），幂等，不怕丢帧导致参数错乱。

**样例**

```
$SET,1,T=30*19                                      改温度阈值为 30
$SET,1,T=28,H=70,CO2=1000,SMK=15,GAS=15,LUX=30*33    六个阈值全量复位
$SET,1,T=35,H=60,CO2=1500,SMK=20,GAS=25,LUX=40*39    六个阈值一起改
```

### 4.2 `$FAN` —— 通风控制

| key | 含义 | 值 |
|---|---|---|
| `AUTO` | 自动通风 | `1`=开 `0`=关 |
| `MAN` | 手动通风 | `1`=开 `0`=关 |

只认 value 的第一个字符是不是 `'1'`。

**样例**

```
$FAN,1,AUTO=1,MAN=0*18     开自动通风，关手动
$FAN,1,MAN=1*36            开手动通风
```

### 4.3 帧类型名的作用

解析器**不校验帧类型名**，只把它当作"不含 `=` 的第一个字段"跳过。
`SET` 和 `FAN` 用的是同一套键值对解析。

帧类型名是给**上位机的日志和代码可读性**用的，也是为将来扩展留位
（比如以后加 `$GET` 请求立即上报、`$CAL` 标定命令等）。

## 五、交互时序

```
下位机                                          上位机
  │                                               │
  ├── $ENV,1,...,*XX\r\n  ──────────────────────► │  每 500ms 自动上报
  │                                               │
  │ ◄──────────────────────  $SET,1,T=30*19\r\n  │  用户改阈值时下发
  │                                               │
  │  解析 → 写配置 → 界面 200ms 内同步            │
  │                                               │
  ├── $ENV,1,...,SPT=30.0,...*XX  ─────────────► │  下一帧里 SPT 变成 30.0
  │                                               │  （上位机据此确认生效）
```

**上位机确认命令生效的正确方式**：发完命令后看后续 `$ENV` 帧里的
`SPT`~`SPL` 是不是变成了你发的值。**不要只看"发出去了"就当成功** ——
设备可能没收到、或者被钳制了。

## 六、上位机（Qt）实现提示

### 校验和

```cpp
// 计算 $ 和 * 之间的内容的异或
static uint8_t xorSum(const QByteArray &payload)
{
    uint8_t x = 0;
    for (char c : payload)
        x ^= static_cast<uint8_t>(c);
    return x;
}

// 用正文（不含 $ 和 *校验）拼出完整帧
static QByteArray makeFrame(const QByteArray &body)   // body 例如 "SET,1,T=30"
{
    uint8_t cs = xorSum(body);
    return "$" + body + "*"
         + QString("%1").arg(cs, 2, 16, QChar('0')).toUpper().toLatin1()
         + "\r\n";
}
```

### 接收

- 用 `QSerialPort::readyRead` 累积字节，**按 `\n` 切行**，再按 `\r` 去掉尾部
- 每行先验 `$` 开头、`*XX` 结尾、校验和正确，**再**解析字段
- **未知 key 必须忽略**（固件以后可能加字段）
- 解析 key=value 时用 `split(',')` + `split('=')`，注意 **value 里不会再出现 `,` 或 `=`**

### 发送

- **必须带 `\r\n`**（见第二节的"重要"提示）
- 波特率 **115200 8N1**
- 建议用 `makeFrame("SET,1,T=30")` 这种形式拼，不要手写校验和

## 七、RS485 与多节点组网

### 已实现的部分

| 项 | 状态 |
|---|---|
| RS485 物理层 | ✅ USART6 + MAX3485（PC6/PC7），已与 CH340 链路并存 |
| 发送方向控制（DE） | ✅ 在 `uart_tx_send()` 里：拉高 → 阻塞发送 → 拉低 |
| `node` 字段校验 | ✅ 解析器会比对；`0` 表示广播，其它值必须等于本机编号 |
| 两条链路独立收发 | ✅ 各自的接收缓冲和诊断计数器分开 |

**DE 时序为什么能这么简单地写**：`HAL_UART_Transmit` 是阻塞发送，**它在
返回前会等 `TC`（Transmission Complete）标志** —— TC 置位代表最后一个
字节真的移出了移位寄存器。

> ⚠️ **如果以后把发送改成 DMA，这段必须重新处理。** DMA 的传输完成中断
> 只代表"最后一个字节写进了 DR"，此时它还在移位寄存器里往外发。那时
> 提前拉低 DE 会把最后一个字节**截断**，而且现象很隐蔽（只是偶尔少一个
> 字节、校验和不过）。正确做法是等 `USART_SR.TC` 位，或改用
> `HAL_UART_TxCpltCallback`。

### 还没做的部分：多设备总线冲突

**当前只有一个节点，所以这个问题还不存在。** 但真挂上多台设备时必须解决：
RS485 是半双工共享总线，两台同时开口 → 数据全废。

**⚠️ 一个硬件上的限制，它排除了整类方案**

模块的 `EN` 把 `DE` 和 `/RE` **短接**在一起，所以：

- `EN=1` → 驱动器开、**接收器关**
- `EN=0` → 驱动器关、接收器开

**发送时接收器是关的，没法边发边听** → **载波侦听（先听后说）和冲突检测
这一整类方案都做不了**。要做的话得把 DE 和 /RE 分开控制，也就是多飞一根线。

**推荐方案：主机点名轮询**

```
上位机                            总线上的从机
  ├── $ASK,1*XX  ──────────────►   ①号：收到，是我的   其它号：无视
  │  ◄──── $ENV,1,...,*XX ──────────┘
  ├── $ASK,2*XX  ──────────────►   ②号应答……
  └── ... 循环
```

- 新增帧类型 `$ASK,<node>`（现有帧格式不用改）
- **被点名的从机才应答**；组网模式下**停用自主上报**
- `node=0` 留给广播
- 零冲突是**结构上保证的**，不靠概率；这也是 Modbus RTU 的做法

**时序预算**：遥测帧约 200 字符，115200 8N1 下约 17ms。每槽给 30ms 有一倍余量：

| 节点数 | 一轮耗时 | 每节点数据更新率 |
|---|---|---|
| 1 | 30 ms | 33 Hz |
| 4 | 120 ms | 8 Hz |
| 8 | 240 ms | 4 Hz |

即使 8 个节点，4 Hz 对"环境监测"也绰绰有余（21VOC 本身才 1 秒一帧）。

**还需要一个"上报模式"**：单机模式自主上报（方便串口助手调试），
组网模式改为点名应答。建议**用显式命令切换**而不是自动判断 ——
隐式自动切换出问题时会很难定位是哪一刻切的。
